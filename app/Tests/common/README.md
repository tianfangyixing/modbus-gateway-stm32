# Configuration v2 host test support

Run from the repository root with CMake 3.24+, a host C11 compiler, and a build tool:

```sh
cmake -S app/Tests -B /tmp/configuration-v2-tests -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/configuration-v2-tests -j 4
ctest --test-dir /tmp/configuration-v2-tests --output-on-failure
```

On this Windows host, prepend `C:/msys64/ucrt64/bin` to PATH and configure with:

```powershell
$env:PATH = 'C:/msys64/ucrt64/bin;' + $env:PATH
cmake -S app/Tests -B "$env:TEMP/configuration-v2-tests" -G Ninja -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe '-DCMAKE_MAKE_PROGRAM=C:/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/Ninja/ninja.exe' -DCMAKE_BUILD_TYPE=Debug
cmake --build "$env:TEMP/configuration-v2-tests" -j 4
ctest --test-dir "$env:TEMP/configuration-v2-tests" --output-on-failure
```

`CONFIGURATION_TEST_SANITIZERS=ON` enables AddressSanitizer and UndefinedBehaviorSanitizer on supported
non-Windows GCC/Clang hosts. Build directories and all fetched dependencies stay outside Middlewares.
The root CMake entry currently includes only `common` and `configuration_codec`; integration owns
adding Service, Management and MQTT suites.

## Public targets and boundaries

- `configuration_model`: the production `configuration.c` and `configuration_binary_codec.c`.
- `configuration_test_lwip`: the repository's real `ip4_addr.c` and `def.c` with host `lwipopts.h` / `arch/cc.h`.
  No fake IPv4/netmask implementation. Transport/netif/RTOS adapters belong to their own suites.
- `configuration_test_mbedtls`: the repository's real Mbed TLS sources, with the firmware configuration
  included and only hardware entropy, platform time and gmtime overrides removed for the host.
  Production certificate algorithms, self-signature checks and capacity limits remain enabled.
  The normal tests use real heap allocation. One explicit negative test injects allocation failure;
  there is no success-returning certificate stub.
- `configuration_test_fixtures`: links the model and exports the header `configuration_test_fixtures.h`.
  It provides `configuration_test_default_payload[48]`, `configuration_test_maximum_payload[8475]`,
  `configuration_test_root_ca[4097]` (including NUL) and `configuration_test_make_maximum()`.
- `unity`: externally fetched Unity 2.7.0, archive SHA-256
  `e84eb301ca7967831e68b1728f911e87fa2d345d8ddb64f897bc2f2ee24a321c`.
  CMake's `FETCHCONTENT_SOURCE_DIR_UNITY` can point to a pre-existing checkout for offline builds.

All vendor inputs are read-only. Libraries are compiled inside the build directory. The common
LwIP include path is PUBLIC for model users; suites that use their own networking options should
put their private adapter path first and ensure matching public type layout.

## Independent fixtures

`fixtures/default_v2.bin` is the literal 48-byte vector from the normative binary specification.
`fixtures/maximum_v2.bin` is generated by `fixtures/generate_vectors.py` using explicit fields and
Python's little-endian `struct.pack`, without calling the C encoder or decoder. The C model builder
sets the same documented field values directly. Tests compare production encoding byte for byte
against the fixed file and decode that file into the independent model.

The maximum vector contains static IPv4 networking, three 253-byte hostnames with label lengths
63/63/63/61, three 256-byte credentials, a 4096-byte PEM, two custom messages with 128-byte topic
and payload, and 16 register collection points with unique 128-byte topics.
Its block lengths are `1 + 21 + 7 + 2 + 512 + 5659 + 2273 = 8475`.
The credential length prefixes at offsets 802, 1060 and 1318 are each `00 01`.

`root_ca_4096.pem` contains one RSA-2048 / SHA-256 self-signed root certificate, with matching
subject/issuer, `CA:TRUE`, and `keyCertSign,cRLSign`. Its original PEM is 1168 bytes; 2928 trailing
LF bytes bring the field to 4096 without adding another certificate or NUL. `.gitattributes`
keeps these fixture bytes unchanged on Windows checkout. The private key is not checked in and is
not needed to regenerate the vectors. OpenSSL `verify -check_ss_sig` and real production Mbed TLS
validation both accept the fixture. Corrupting the signature is rejected by the production validator.
This certificate is only for host tests, never for deployment or trusting a real broker.

With 115200 bit/s, 8N1, and one poll/second per point, each register transaction uses
`2*1750 + ceil(15*10*1000000/115200) = 4803` microseconds/second.
The total is 76848 microseconds/second (7.6848%), below the 50% limit. Setting 1200 bit/s is
independently tested to exceed the limit and must be rejected.

Regenerate fixed binary files (no key, network or production algorithm required):

```sh
python app/Tests/common/fixtures/generate_vectors.py
```

The encoder's existing precondition remains: only call it with a model that has passed validation.
Invalid model bounds/NUL tests invoke `configuration_validate`; malformed wire tests invoke decode.
Tests never inspect unspecified failed outputs, depend on the order of unrelated validation errors,
or compare whole configuration structs with `memcmp`.
